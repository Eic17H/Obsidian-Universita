# Range searching

## Search

It's an important topic in computer science. In *The Art of Programming* by Donald Knuth, there are two books, 300 pages each, one titled *Searching* and one titled *Sorting*. The main thing about the computational complexity of searching is the difference between a sorted set and an unsorted set.

We search with a key. In an unsorted set we compare the key with every item $O(n)$. In a sorted set we can use binary search, $O(\log n)$.

After a search, you may either return yes/no (decisional algorithm), an amount of occurrences or a position. Decisional algorithms ("is the key in the set?") stop as soon as it finds one example, but if you need to count the occurrences you really need to read through the whole unsorted set.

If you need to perform one search, there's no reason to sort the set, because you sort in $O(n \log n)$, but you search an unsorted set in $O(n)$. For multiple searches, it's best to sort in advance.

We usually search with one key. We're used to that. But what if we searched with *two keys*? How? Two keys defining an ==interval==, usually a closed interval, like ==🔴$[x:x']$==. Now having a decisional algorithm isn't as intuitive.

Let's represent our data as numbers, points on the real line. The usual set would be "I give you a real value, is this real value in the set or not?". But now the key is an interval: I can place the two end points on the real line.

Let's assume that my set is stored in some way, in a sorted way. What can I do? Which means, how can I algorithmically implement my search?

If my set is unsorted, I can do nothing but compare every element with my interval, which is more or less exactly the same as the search with a single key, it's $O(n)$.

But we're working with a sorted set. My solution, binary search for the least element greater than ==🔴$x$==, binary search for the largest element smaller than ==🔴$x'$==, take all elements between those indices.

Real solution, using a [[ABR|binary search tree]], a non-linear structure. We usually talk about rooted trees: a tree with an explicit root and where all other nodes are descendants of the root, and nodes with no descendants are leaves. In a binary tree, each node has at most two children. For a tree to be a search tree, elements within it are sorted, and we have two ways to build a BST: the keys are in every node, the keys are only in the leaves (and the internal nodes are only guidance nodes). Of course, if you put your keys in every node, you are saving space, but if you only put keys in the leaves, you double the number of nodes (though the keys might be a lot larger than guidance nodes). But managing dynamically a BST where the keys are only in the leaves is a lot simpler.

The second question you may ask is how you build the BST, there are two ways: recursively (top-down) or iteratively (bottom-up). The sorting phase is preprocessing for both ways.

We can't always have a complete tree (for example if we need six leaves), but we can use a balanced tree. For example $6$ is between $2^2$ and $2^3$, so we take the complete tree with $4$ leaves, and add children, because adding two children to a leave gets you one more key.

I put keys in the leaves. In each internal node, I put the largest value in the left subtree. How do I search in such a tree? I compare the query key with the current node, if the query key is smaller I go to the left subtree, right subtree otherwise, recurse. How do you query for an interval? I already gave my solution, but it's incompatible with our data structure. The real solution is to simple-query for ==🔴$x$== and simple-query for ==🔴$x'$==, both will end up in a leaf. Think of the path they take: at the root, they may go in the same direction or in different directions. What we are looking for is the ==split node==, the internal node where (if it exists) the two paths diverge. Basically we're looking for the subtree that contains all the nodes we're looking for. If the root is the split node, the whole tree is our subtree. If we have no split node, we just check if the leaf is in the interval.

![[Pasted image 20261104102051.png]]

Let's look at the shape of this tree. We don't know the keys, we just know that those are the paths taken by ==🟢$x$== and ==🔴$x'$==. The only thing we know for sure is that the ==🔵leaf/leaves marked in blue== is in our output set.

At the split node, we know that all the keys in the right subtree are larger than $x$, and all the keys in the left subtree are smaller than $x'$. Not just at the split node, but every time $x$ goes left or $x'$ goes right. And the ==🔵blue leaf== is in the intersection of those sets.

Now, we just need to check individually whether the two ==🟡leaves marked in yellow== are in the set.
