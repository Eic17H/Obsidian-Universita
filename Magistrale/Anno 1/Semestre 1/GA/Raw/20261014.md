## Convex decomposition

Bad news: the convex decomposition problem is a very hard problem. Convex decomposition is splitting a concave polygon in convex portions.

We don't have a better way for convex decomposition than the following, look at this, it's quite curious. The best way to find the convex decomposition of a polygon is the following:

## Triangle decomposition

Let's assume we can do it. We proved we can do it.

The complexity is:

* Adding diagonals, $O(n)$, outer loop
	* Inner loop, find diagonal (compare a segment with all other edges), $O(n)$

In total, $O(n^2)$. For the time being that's okay.

Find the leftmost vertex, find the ajdacent vertices, if the connecting segment is a diagonal that's fine otherwise pick another one with a certain method, remove our three vertices from the list and recurse.

```JS
function triangulate(shape P) {
	if (P.size() == 0)
		return [];
	v = P.leftmostVertex();
	u = v.next();
	w = v.prev();
	return (v,u,w)::triangulate(P \ v \ u \ w);
}
```

And we proved that any triangulation of this shape is made by the same amount of triangles.

## Cameras

Our attempts so far:

2. Place cameras on diagonals: $\text{mess!}$

Now... Let's look at one triangle. Let's color each vertex a different color. Let's look at a triangle that shares two vertices with it, and apply the same logic: two vertices are already colored, so the other one only has one option for a color. Let's apply this to every triangle, and this way we can give that property to every triangle. Now, we've grouped vertices in three groups, each with a different color. We want to make it so that we can solve the camera problem by placing cameras only on one of the tree groups.

1. Three different labels for vertices (colors)
2. Each triangle with vertices of different color

We need to find the dual graph of the shape.

> **==Dual graph==**: Node for triangles, arcs for adjacency.

So it has $n-2$ nodes and $n-3$ arcs, because diagonals determine adjacency. One less arcs than nodes, but that's a property of trees! But that's not enough to define a tree, we also need to have no loops, which means that removing any arc splits the graph in two (every arc is breach). but we get that property by using diagonals. The dual graph of our triangulated polygon is a tree.

We can explore a tree in at least two ways: depth first and breadth first.

You cannot triangulate a polygon in $O(n)$. The proof of Chazelle and its $O(n+\ldots)$ algorithm is so complex that there is no implementation, it's a beautiful theoretical result but in practice it's almost unusable.

A more practical results gives us a complexity of $O(n \log n)$. There's a big difference with $n^2$.

## Ear-cut algorithm

> **==Ear== of a polygon**: a partition of the polygon delimited by three consecutive vertices and the segments connecting them.

That means that two segments are sides, and one is a diagonal.

![[Pasted image 20261014101600.png]]

> **Theorem**:
> Every polygon has at least $\text{two}$ ears.

Finding all triples of consecutive edges is $O(n)$, for each we need to know if the segment is a diagonal which takes $O(n)$, in total it's $O(n^2)$.

In order to get it down to $O(n \log n)$, we need to introduce a new type of polygon.

## Monotone polygon

> *This doesn't mean they're boring.*

The analytical concept of monotonicity:

> **Monotone function**
> $y = f(x)$
> $\forall x_i,x_j,\ x_i > x_j \Rightarrow f(x_i)\geq f(x_j)$

For a strictly monotone function, take out the equals sign from the disequation.

> **Monotone polygons** (with respect to a direction)

Our direction will be the $y$ axis, so we'll talk about y-monotone polygons.

> **y-Monotone polygons**
> Take the highest point (largest $y$) and the lowest point (smallest $y$).
> To get from the highest to the lowest point, you have two paths: the left chain and the right chain.
> If the polygon is y-monotone, the two chains of edges are themselves monotone, in the sense that every vertex of the chain going from the highest to the lowest has a $y$ that is smaller or equal to the previous.

![[Pasted image 20261014102733.png]]

The two chains are defining monotone functions.

Monotone polygons have a nice property that we'll prove next week.

> We can triangulate monotone polygons in...........................................drums rolling................................................ $O(n)$!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!111

It's very nice. Normal polygons, $O(n^2)$, monotone polygon $O(n)$.

How can we transform a normal polygon into a monotone polygon? We cannot, but we can split a normal polygon into a monotone polygon.

The goal is:

1. Split $P$ in monotone parts: ==partition==;
2. Triangulate each part;

If I can perform both steps, and they're sequential, and if none of them is more complex than $O(n \log n)$, then the whole algorithm is $O(n \log n)$. The second one is $O(n)$, next time we'll prove the first part.
