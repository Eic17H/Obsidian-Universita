## Data structures

We glossed over them last time. What do we need to perform the partitioning?
* For storing the polygon: a ==dcel== $D$
* For finding the other end point of the turn diagonal: a ==queue== $Q$ (kew kew, kew kew, very funny to say kew kew -Scateni)
* For the status of the algorithm (the set of (left) edges currently crossed by the sweeping line, which changes at event points (vertices)): a ==BST== $T$

The ==dcel== with the polygon inside is the input of our process, that's the main part. From it, we want to produce the partition, and we'll see that the partition can be in the same data structure: in other words, we'll see that the algorithm is changing the data structure given in input to produce the output.

We saw an algorithm that is inserting diagonals into a polygon. One important thing is that one end point of the diagonal is easy to find, because it's just every turn vertex. It can happen that we insert a diagonal from a split to a merge, but in general we can assume that doesn't happen, so let's just say it's $O(n)$ diagonals. Constructing $Q$ is $O(n \log n)$.

The edge $e_i$ is the edge ending in vertex $v_i$, clockwise. $e_{i-1}$ starts in $v_i$.

Basically, to handle each type of vertex:
* Start: $T.insert(e_i)$, $helper[e_i]=v_i$
* End: if $helper[e_{i-1}]$ is a merge, make a diagonal from it to $v_i$, in all cases $T.remove(e_{i-1})$
* Split: search $e_j$, directly to the left of $v_i$, in $T$, then connect $v_i$ and $helper[e_j]$, $helper[e_j]\leftarrow v_i$, insert ei in T and set heplperei to vi (no need to know what type of vertrex helperei is, it might be a merge vertex)
* Merge: if $helper[e_{i-1}]$ is merge then diagonal $v_i$-$helper[e_{i-1}]$, regardless $T.remove(e_{i-1})$, search $T$ for $e_j$ to the left of $v_i$ and set its helper as $v_i$ maybe

The number of end, start and turn vertices are connected. There are as many start vertices as end vertices, because that's how many monotone parts there are. At the same time, I need enough turn vertices to make enough diagonals to make those monotone parts.

Complexity. Of course. It needs to be better than ear-cut, which is between $O(n^2)$ and $O(n^3)$. For small polygons, a quick and dirty algorithm like ear-cut is fine, this new algorithm is really complicated:
1. Sorting: $O(n\log n)$
2. Cycle over vertices: $O(n)$
	1. Process the vertex as we just saw: $O(\log n)$ (max of branches)
		1. start $O(1)$
		2. end $O(1)$
		3. split: search $O(\log n)$
		4. merge: search $O(\log n)$
		5. regular: search $O(\log n)$

The cycle is thus $O(n \log n)$, sum step 1 and step 2 and you get $O(n \log n)$. For now, we're winning, siamo in testa alla fine del girone d'andata, stiamo vincendo, e se continuiamo così, we have enough chances to win. We still have to triangulate the monotone parts.

The funny thing is that the triangulation of a monotone polygon is roughly an ear cut.

The idea behind the triangulation of a polygon like this is very simple. First of all, there are two vertices that are *==🔵special ones==*, like \[nome], those being the start and end vertex.
