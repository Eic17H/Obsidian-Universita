# Point location

Input: A subdivision $S$, a query point $q$. Output: the face of $S$ containing $q$.

We introduced a bounding box to avoid infinity, because infinity is rarely nice. The vertical extension thing, trapezoidal map. Why did we do that? Time complexity is $O(\log n)$, but the memory footprint is $O(n^2)$.

There might be a conceptual problem: we always draw trapezoids with the parallel sides being horizontal. We aren't used to thinking of trapezoids with vertical parallel edges. But of course, with vertical extensions, they are. Well, we could use horizontal extensions, and we'd have *normal* trapezoids, but we're using vertical extensions. Anyway, the point is, if we shrink the smaller base down to $0$ length, we get a degenerate trapezoid, a triangle. So:

> A triangle is a trapezoid with one parallel edge of length $0$.


![[Pasted image 20261124114236.png]]

So we have our trapezoidal map. In all cases, either the top or the bottom side (or both) is a a portion of an edge of $S$ (one may be a portion of an edge of the bounding box). While the vertical sides are portions of vertical extensions (or vertical edges of the bounding box in some cases). And vertical extensions are defined by vertices.

> Each trapezoid $\Delta$ has two vertical sides defined by $leftp(\Delta)$ and $rightp(\Delta)$.

Memory footprint of $T$:

Edges of the bounding box, plus the vertical extensions (at most two vertices per original edge), plus the vertices created by the vertical extensions (each vertex makes two extensions, each extension has at most two vertices), so it's $4+2n+2(2n)=6n+4$ new vertices. But that's an upper bound, in practical cases you typically don't ever reach this value. But it's $\ni O(n)$.

Now, the faces. Each face is. #todo: foto dal telefono.
* The left endpoints can be $leftp$ twice.
* The right endpoints can be $leftp$ only once.
* In the bounding box we have one $leftp$.

$leftp$s are biunivocal with faces, so we have as many $leftp$s as we have faces. So, with $n$ left endpoints and $n$ right endpoints, we have at most $2n+n+1$ faces, and that is also $\ni O(n)$.

So our intuition was correct, if you stop the vertical extensions at edges, you will only refine where you do need to refine.

So, we passed from $4$ faces to $21$ (upper bound $34$ #todo: check values), with the important property of trapezoids, convexity.

We could store our trapezoidal map as a $DCEL$, but in this case it's even too much, because the structure of a trapezoidal map is very simple.

## Data structure for $T$

It's a collection of edges, vertices and faces. The edges are an input of the problem, so we have for sure an edge table $E$ ($n$). Since the end points of the edges are vertices, we have a vertex table $V$ ($\leq 2n$). Most importantly, we have a face table, and in order to define a face we need four elements and only four elements.

That's why the $DCEL$ is too much, it's too flexible, it can define any type of shape, but in this case we're only defining quadrilaterals.

We define a quadrilateral as $leftp$, a pointer to an element of $V$. And a $rightp$, also a pointer to $V$. Then we have what we called $top(\Delta)$ and $bottom(\Delta)$, which are edges, two pointers to $E$.

A face $\Delta'$ is adjacent to $\Delta$ if they share a vertical side.
![[Pasted image 20261124121804.png]]

The adjacent faces are $lu$, $ll$, $ru$ and $rl$. Those are four pointers to $F$.

An edge is defined by two pointers to vertices, $lendp$ and $rendp$. A vertex is defined by two integers, $x$ and $y$.

So it's:
* $E = list(lendp:\to V, rendp:\to V)$.
* $V = list(x:num, y:num)$.
* $F = list(leftp:\to V, rightp:\to V, top:\to E, bottom:\to E, ll:\to F, lu:\to F, rl:\to F, ru:\to F)$.

```C
typedef struct V {
	int x;
	int y;
}

typedef struct E {
	V* lendp;
	V* rendp;
}

typedef struct F {
	V* leftp;
	V* rightp;
	E* top;
	E* bottom;
	F* ll;
	F* lu;
	F* rl;
	F* ru;
}

typedef struct T {
	E edges[];
	V vertices[];
	F faces[];
}
```

## Building a trapezoidal map

The algorithm is iterative. We iterate over the edges of $S$, inserting them one at a time.

![[Pasted image 20261124122852.png]]

Now, after adding two points, we have this in our data structure $R$. We build a companion data structure, we'll call it $D$ and you'll see why.

![[Pasted image 20261124123151.png]]

This is the search data structure.

Start from the root. If the $x$ is smaller, you're in $A$. If it's bigger, compare to $q_1$. To the right, you're in $D$. To the left, your $x$ is shared with a point in $S_1$, so you have to compare $y$, so if you're above you're in $B$, and if you're below you're in $C$.

Well, you aren't *quite* comparing $y$ as it varies along $S_1$.

It's interesting how at fist we perform simple comparisons, the cost is negligible. The complexity is $O(1)$ like computing the determinant of a $3 \times 3$ matrix, but of course it's much much simpler in practice.
